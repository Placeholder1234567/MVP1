# Daily summary response ownership

The Overview passes the current home to one `LomiSummary` component. Its prior request completion assigned the response without verifying that home or the viewing context still matched. Clearing on home change alone did not stop an older response from returning afterward. Loaded summaries also survived privacy unlock, and pending navigation had no completion guard.

The component now uses the existing in-memory response guard and an abort controller. A request captures the current agency/profile/role/home assignments/features/timezone, current and requested home, home existence and privacy state. A completion must still belong to that context and controller, while online, visible and outside navigation. Home/context/privacy changes clear the loaded summary and feedback; navigation clears them before destination loading finishes, and disposal invalidates completions. Offline interruption preserves an already loaded same-context summary for reading and disables fresh requests. Reconnect and unlock require an explicit new summary request. The displayed home label comes from the accepted server snapshot.

Server record selection, summary prompts, fallback counts, operational next-step rules, entitlements and authorization remain unchanged. Aborting UI acceptance does not claim to cancel a server invocation or provider processing already started. Nothing automatically writes a clinical record or initiates a next step.

`tests/e2e/lomi-summary-response.spec.ts` holds real console/demo summary responses on desktop and phone: two home requests released out of order; loaded-data privacy removal with a held refresh and explicit recovery; and a response released while the destination's real data load is held. Offline reading, disabled actions, no automatic reconnect request, axe and overflow are checked. No synthetic summary payload replaces the actual API response. GitHub CI executes the browser tests; local type checks do not establish their result. Live-model summary factuality and staff usefulness remain unverified acceptance gates.
