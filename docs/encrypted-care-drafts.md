# Encrypted care form recovery

Health, incident, and attendance forms save unfinished answers in the existing encrypted OPFS PowerSync database. `care_drafts` is declared only in `app-schema.ts` with `localOnly: true`; it is absent from generated `syncedTables`, sync streams, and server schema. It cannot enter the PowerSync CRUD upload queue. No browser key/value storage, separate plaintext files, providers, migrations, or clinical auto-submission are introduced.

Each device/profile/client/section has at most one versioned draft, limited to 128,000 JSON characters. The whitelist retains form answers and step position, excluding signatures and UI confirmation state. Writes debounce for 500 ms and are serialized. A visible “Recovery draft saved on this device” notice follows successful storage. A sudden browser/process termination before that notice can lose the latest unfinished keystrokes; native leave still warns, starts a flush, and never claims that asynchronous work can delay operating-system termination.

The encrypted database close lifecycle attempts every registered draft flush before closing. Privacy masking remains immediate; failure cannot leave the database open. Failed writes retain the newest in-memory snapshot for retry and show a generic error after unlock. Unsigned current answers remain in memory behind the existing privacy shield. Each store is bound to its original encrypted database handle; close-time flushes select only stores with that exact handle. Unlock creates a new scoped store and restores the current same-profile/client/section answers without retargeting an old store into another file. Database reads use all three scope keys and profile-specific encrypted database files. Restored answers are shown only after an explicit Resume action. Discard waits for local deletion; failed deletion leaves the current form and warning intact. Successful clinical saves clear the recovery copy; a failed cleanup remains visibly actionable, so users should check saved records before resuming an older copy.

Incident signatures are never persisted or restored. Medication confirmation recovery is deliberately excluded; existing medication forms retain their navigation safeguard. Recovered health observations require review and explicitly explain that a newly saved record gets the current save time. Incident/attendance drafts from another agency-local calendar day remain visible read-only with the original date; Resume is blocked to prevent recording them as today. Users can recover the facts manually through their agency process or explicitly discard them.

The generated sync-schema workflow is unchanged. The existing device-schema overlay is the authoritative source for this additional local-only table. Health field/kind whitelists derive dynamically from the domain definitions, allowing supported new observation fields without persisting arbitrary keys.

Focused unit checks cover local-only exclusion, profile isolation, debounce/latest-value ordering, delete races, retry after storage failure, prior-day safety, stale-write acknowledgements, and rejecting foreign database handles. The desktop/phone browser case closes and reopens real tabs in the same encrypted device profile, explicitly resumes all three form types, checks discard durability and fresh incident signature requirements. Browser execution is reserved for CI; local validation uses test discovery, lint/types, build, and offline-artifact checks.
