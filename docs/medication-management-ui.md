# Medication definition management

`/dashboard/medications` is guarded by the existing dashboard supervisor/admin check and `mar` entitlement. A small `mar`-gated link in Care reports provides discovery; direct route access does not require reporting. No navigation, people/staff/setup, care charting, authentication or notification screens are changed.

The home/person selectors initialize when local sync supplies the first home, without overwriting a chosen scope. Authoritative definitions are loaded through medication APIs. Active definitions appear by default; stopped definitions are behind an explicit disclosure, read-only except for viewing their history. Editing and stopping never rewrite existing MAR entries. Stopping requires confirmation and is described as recording an existing authorized change, not prescribing advice.

The form copies authorized prescription/pharmacy wording only: name/strength 200 characters, dose 200, route 100, notes 4,000. Scheduled mode accepts one to 24 exact HH:mm times separated by commas in the agency time zone. PRN mode has no scheduled times and requires up to 2,000 characters of as-needed instructions. Switching modes preserves unfinished text in memory while submitting only the selected mode and explicitly clearing incompatible fields. No future-order picker or AI autofill is added.

Change history shows only the API's actor/action/time timeline, not old/new prescription snapshots. Existing backend audit records remain the source for before/after details. Loading errors and list limits are reported plainly; stale history is cleared on scope changes and late responses cannot cross the selected person. Mutations and discarded drafts have explicit guards; failures and offline saves retain entries. Management writes are not queued offline, and no PHI is placed in URLs, logs or browser storage. The surrounding privacy lock remains in force. Closing a page still discards unsaved in-memory drafts.

The synthetic desktop/390px browser case covers bad-time rejection, scheduled creation, conversion to PRN, active/default and stopped read-only views, stop cancellation/confirmation, actor/action/time history, offline retention, cancelled navigation and a clean PIN-unlocked reload with automatic scope initialization. It runs an axe WCAG check on this route and attaches successful screenshots. Actual browser execution is reserved for CI; local checks only discover/typecheck the test. No local automated browser, provider, database reset or seed is used.
