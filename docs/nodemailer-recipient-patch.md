# Nodemailer recipient parsing patch

The combined main lockfile selected Nodemailer 10.1.1. The production dependency audit in PR306 reported one moderate package finding containing three recipient-parser advisories: [nested comments](https://github.com/advisories/GHSA-8c8m-p3m8-cjg8), [group comments](https://github.com/advisories/GHSA-m943-m63m-w62w) and [quoted local parts](https://github.com/advisories/GHSA-85x2-q946-cp5h). Upstream identifies 10.1.4 as patched; its [release notes](https://github.com/nodemailer/nodemailer/releases/tag/v10.1.4) describe the parser changes.

The package minimum is now `^10.1.4`, with the lockfile selecting exactly 10.1.4. The npm CLI generated the lock change; no broad audit fix, forced override, major upgrade or unrelated dependency update is included. Guad uses Nodemailer only in the SMTP branch when an SMTP URL is configured. The SES implementation is separate. This dependency finding does not establish that Guad accepted an affected address or delivered to the wrong recipient.

`tests/unit/messaging/recipient-envelope.test.ts` uses Nodemailer's stream transport to construct synthetic messages entirely in memory. It opens no SMTP connection, sends no email and calls no real provider. Ordinary mailboxes, nested comments and semicolons inside group comments must produce exactly the intended single-recipient envelope. The quoted-local-part case requires one recipient at the intended domain; the formatter normalizes angle brackets in local parts, so this test deliberately does not claim verbatim RFC mailbox syntax support. All three advisory shapes selected the unintended domain/recipient in a local 10.1.1 stream-transport comparison.

The first quoted-local-part assertion expected verbatim syntax, which the formatter does not preserve. Source inspection of its address normalization established the narrower security invariant above; the exact-envelope assertions for the other cases are retained. No existing CI assertion, timeout, retry count, provider behavior or authorization rule is weakened.

After the patch, the local production-only audit reports zero findings. A development-inclusive audit still reports eleven package records (nine moderate, two high), including patchable CLI transitive dependencies and the previously identified toolchain compatibility issues.
